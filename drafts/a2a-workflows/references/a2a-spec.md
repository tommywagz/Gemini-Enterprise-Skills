# A2A Protocol Reference Specification

This document provides a reference for the Agent2Agent (A2A) protocol—an open standard designed to enable communication and interoperability between disparate AI agent systems.

## 1. Overview
- **Purpose:** Open standard for agent-to-agent interoperability, allowing agents built on different frameworks (e.g., LangGraph, CrewAI, Google ADK, Genkit) to discover each other's capabilities, negotiate interaction modes, and collaborate on tasks securely.
- **Normative Source:** Protobuf definitions (`specification/a2a.proto`). A JSON Schema is published at `docs/spec/a2a.json`.
- **Communication Bindings:** Supports JSON-RPC 2.0 (HTTP/SSE), gRPC, and HTTP/REST.

## 2. Core Data Objects

### 2.1 AgentCard (`/.well-known/agent-card.json`)
Describes an agent's identity and capabilities for discovery.
- **Identity Metadata:** `name`, `description`, `version`.
- **Supported Interfaces:** List of `AgentInterface` containing URLs, protocol bindings, tenant, and protocol version.
- **Capabilities:** Flags for `streaming`, `push_notifications`, `extended_agent_card`, and `extensions`.
- **Skills:** List of `AgentSkill` containing `id`, `name`, `description`, `tags`, and `examples`.
- **Security Schemes:** OpenAPI-style configuration for authentication (API Key, OAuth2, OIDC, mTLS, HTTP Auth).
- **MIME Input/Output Modes:** Supported media types (e.g., `text/plain`, `application/json`).

### 2.2 Task
Represents a stateful, async or sync execution unit of work.
- `id`: Unique identifier for the task.
- `context_id`: Conversational context ID.
- `status`: A `TaskStatus` object containing `state`, `message`, and `timestamp`.
- `history`: List of `Message` representing the task's conversational history.
- `artifacts`: List of `Artifact` (tangible outputs produced).
- `metadata`: Custom structured metadata.

### 2.3 TaskState (Enum)
Represents the current lifecycle state of a task.
- `SUBMITTED`: Task has been queued or received.
- `WORKING`: Task is actively being processed by the agent.
- `COMPLETED` (Terminal): Task finished successfully.
- `FAILED` (Terminal): Task failed during execution.
- `CANCELED` (Terminal): Task was explicitly cancelled.
- `REJECTED` (Terminal): Task was rejected (e.g. invalid inputs or policy violation).
- `INPUT_REQUIRED` (Interrupted): Execution paused awaiting human/caller input.
- `AUTH_REQUIRED` (Interrupted): Execution paused awaiting authentication credentials.

### 2.4 Message & Part
- **Message:** Contains `message_id`, `role` (`USER` or `AGENT`), `parts`, `context_id`, and `task_id`.
- **Part:** A union structure containing one of:
  - `text`: Plain text payload.
  - `raw`: Raw binary data (bytes).
  - `url`: A reference URL.
  - `data`: Arbitrary structured JSON data.
  - Includes a `media_type` (MIME type) and `filename` where appropriate.

### 2.5 Artifact
A tangible output generated by a task. It contains one or more `Part` objects and associated metadata (e.g., download URLs, identifiers, or descriptions).

## 3. RPC Methods

The authoritative list of RPC methods implemented by A2A endpoints:

| Method | Request | Response | Description |
| :--- | :--- | :--- | :--- |
| `SendMessage` | `SendMessageRequest` | `SendMessageResponse` | Initiates or continues a task. |
| `SendStreamingMessage` | `SendMessageRequest` | `stream StreamResponse` | Sends message and receives real-time SSE updates. |
| `GetTask` | `GetTaskRequest` | `Task` | Retrieves current task state. |
| `ListTasks` | `ListTasksRequest` | `ListTasksResponse` | Filter and paginate tasks. |
| `CancelTask` | `CancelTaskRequest` | `Task` | Requests cancellation of a task. |
| `SubscribeToTask` | `SubscribeToTaskRequest` | `stream StreamResponse` | Subscribes to updates for an existing task. |
| `GetExtendedAgentCard` | `GetExtendedAgentCardRequest` | `AgentCard` | Fetches detailed metadata after authentication. |

### 3.1 Streaming Events (`StreamResponse`)
Streams return a payload containing one of:
- `task`: Full task state.
- `message`: A discrete message part.
- `status_update`: `TaskStatusUpdateEvent` containing `taskId`, `contextId`, and `status`.
- `artifact_update`: `TaskArtifactUpdateEvent` containing `taskId`, `artifact`, `append` flag, and `last_chunk` flag.
