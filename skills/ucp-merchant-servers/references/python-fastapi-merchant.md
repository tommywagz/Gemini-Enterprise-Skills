## 1. Directory Structure

A production-grade Python UCP server typically adheres to this layout:
```
rest/python/server/
├── server.py                 # Application entry point, starts uvicorn
├── config.py                 # Configuration flags, database paths, and lifespan
├── enums.py                  # UCP-compliant error/severity and message types
├── exceptions.py             # Custom exceptions mapped to UCP error responses
├── dependencies.py           # Dependency injection (headers, signatures, database connections)
├── models.py                 # Unified Pydantic models for request/response serialization
├── generated_routes/         # Autogenerated routing files from UCP OpenAPI schemas
│   └── ucp_routes.py
├── routes/                   # Custom business implementations
│   ├── discovery.py          # Publishes profile at /.well-known/ucp
│   ├── order.py              # Order state management and simulation hooks
│   └── ucp_implementation.py # Implements checkout/cart capability routing callbacks
└── services/                 # core database & checkout transaction services
    ├── cart_service.py
    └── checkout_service.py
```

## 2. Dependencies & Tooling

The recommended Python management tool is **uv** (by Astral).
- **Initialization & Packages:**
  - Fast package installation and virtual environment synchronization via `uv sync` or `uv run`.
  - Defined in `pyproject.toml` or `requirements.txt`.
- **Database:**
  - SQLite database files (`products.db` and `transactions.db`) are used for lightweight transactional storage.

## 3. Database Schema Import

Initialize databases using CSV files mapped to the UCP schema:
```shell
mkdir -p /tmp/ucp_test
uv run import_csv.py \
    --products_db_path=/tmp/ucp_test/products.db \
    --transactions_db_path=/tmp/ucp_test/transactions.db \
    --data_dir=./test_data/flower_shop
```

## 4. Execution Parameters

Run the server with explicit options for signature enforcement and security:

```shell
uv run server.py \
   --products_db_path=/tmp/ucp_test/products.db \
   --transactions_db_path=/tmp/ucp_test/transactions.db \
   --port=8182 \
   --require_signatures=true \
   --allow_insecure_profile_urls=false
```

### Key Parameters:
- `--require_signatures`: Rejects unsigned or corrupt requests with `401 signature_invalid` if enabled.
- `--allow_insecure_profile_urls`: MUST be `false` in production. Allows local HTTP testing/demos when `true`, bypassing SSRF protections.
- `--webhook_signing_key`: Path to P-256 EC or Ed25519 PEM key to sign outgoing order webhooks. If omitted, generates an ephemeral public/private key pair on boot.

## 5. Implementation Core Patterns

### 5.1 Route Wrapper Override (`routes/ucp_implementation.py`)
To keep codebase maintenance clean, decouple generated routing files from manually-authored business operations by mapping operations using a route injection dictionary:

```python
# In ucp_implementation.py:
async def create_checkout(
  checkout_req: UnifiedCheckoutCreateRequest,
  common_headers: dependencies.CommonHeaders,
  idempotency_key: str,
  checkout_service: CheckoutService
) -> UnifiedCheckout:
  # Business validation and checkout creation logic
  ...

IMPLEMENTATIONS = {
  "create_checkout": create_checkout,
  "get_checkout": get_checkout,
  "update_checkout": update_checkout,
  "complete_checkout": complete_checkout,
}

def apply_implementation(router: APIRouter) -> None:
  new_routes = []
  for route in router.routes:
    if isinstance(route, APIRoute) and route.operation_id in IMPLEMENTATIONS:
      impl = IMPLEMENTATIONS[route.operation_id]
      new_route = APIRoute(
        path=route.path,
        endpoint=impl,
        methods=route.methods,
        operation_id=route.operation_id,
        # override response model with unified type
        response_model=impl.__annotations__.get("return", route.response_model),
        dependencies=route.dependencies,
      )
      new_routes.append(new_route)
    else:
      new_routes.append(route)
  router.routes = new_routes
```
This pattern ensures that changes to autogenerated schemas do not break core business logic handlers, enabling agile iteration cycles.
